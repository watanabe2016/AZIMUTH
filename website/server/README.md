# 官网访问与下载统计

`Update-Statistics.ps1` 由 Windows 计划任务每分钟运行，从本站 IIS W3C 日志增量汇总数字。不需要数据库或浏览器写入接口。

- `visits`：首页、插件页和皮肤页的成功 GET 浏览次数（HTTP 200 / 304），不是独立访客数。
- `downloads`：官网安装包的成功 GET 请求（HTTP 200 / 206，且 Windows 状态为 0）。同一 IP 与 User-Agent 连续 30 分钟内的重复下载和分段请求合并。它不是安装数，也不能证明用户实际保存或安装了软件。
- 排除可识别的机器人、命令行客户端和监控。不能识别全部机器人，也不能跨设备识别同一人。
- 不包含 GitHub Release 等其他渠道的下载量。
- 首次执行补录现存日志；计数持久化在网站目录之外，后续删除旧日志或更新网站不会清零。
- IIS 日志存在写入延迟，加上每分钟汇总，数字通常延迟 1–2 分钟。

## 部署配置

默认站点日志目录为 `C:\inetpub\logs\LogFiles\W3SVC2`，部署时应以实际站点 ID 为准，通过 `-LogDirectory` 指定。

使用 SYSTEM 身份运行每分钟计划任务。状态目录为 `C:\AZIMUTH-Web\statistics`；仅将其 `public` 子目录映射为网站 `/statistics/` 虚拟目录。**不要将整个状态目录映射到公网**。

脚本使用命名互斥锁防止并发执行，使用原子文件替换保存状态及公开数据。私有去重键为带随机盐的摘要，不向前端输出 IP 或 User-Agent。状态文件损坏时任务报错并保留上次公开数据，不自动清零。恢复时从备份还原状态文件，避免重复计数。

公开接口 `/statistics/stats.json` 只包含汇总数字、统计起点和更新时间。前端每分钟读取，失败时展示不可用提示，不使用本地虚构数字。静态本地预览没有该服务时显示 `—`。

部署备份应同时保留 `state.json` 和公开的 `stats.json`；运维时避免丢弃私有状态。不要把运行时日志、状态或盐上传到 GitHub。
